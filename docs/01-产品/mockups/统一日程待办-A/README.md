## 语义口径

- `EVENT`：某个时刻发生、需要参加的事，例如会议、考试、车次。
- `TASK`：在截止时间前需要完成的事，例如交材料、报名、缴费。
- 没有截止时间的待办进入「待安排」，不强行塞进日历。

## 交互规则

1. 新建统一从一个入口进入，先选类型，再填内容。
2. 入口方案里推荐 B：类型始终可见，切换成本最低；A 适合首次使用，C 最贴近现有编辑页但不够显眼。
3. 待办按截止日进入日历当天，和日程按时间排序；日程用日历图标，待办用圆圈勾选。
4. 待办页继续使用时间线，按月份和日期分组，所有有日期的安排在前，「待安排」在最后。
5. 图片识别结果页同时展示两类结果，类型标注清楚，用户可以改类型后再导入。
6. 判断不确定时不静默猜错，停在确认页让用户选择。

## 当前不做

不把现有日程的单时间点模型立刻改成持久化的「起止时间」。老师说的「待办 = 从现在到截止时间」先作为时间线展示区间理解，避免牵动 API、重复规则、提醒和双后端。
