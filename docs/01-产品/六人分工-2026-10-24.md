# 时纪流 · 六人任务分工（2026-10-24）

> 这份文档写给六个人一起看。先看“一分钟版”，再找自己负责的部分。
> 看不懂代码文件名没关系，最后有术语解释和文件归属表。

> 分工原则：重要功能交给熟悉项目的人；经验少的同学先从界面、测试、素材这类容易上手的任务开始，熟悉项目后再增加任务。这样安排是为了让项目稳定推进，不代表谁不重要。

## 三、每个人具体要交什么

### 成员 1：识别和 AI

**目标：** 图片和聊天截图识别得更快、更准。

**要做的事**

- 完成任务 1：优化图片识别日程的速度。
- 完成任务 12：识别聊天截图里的日期，比如“19 日”“下周三”“今晚”。
- 负责 4/8 长期研究线，先准备评测数据，不要一开始就承诺模型上线。

**最后交付**

- 20 条真实样本和一份准确率基线。
- 解析速度有明显提升，字段准确率不能下降。
- 聊天截图的日期推断有测试。
- 每两周有一份实验记录，别人能照着复现。

**注意**

- 原始截图只在手机本地识别，不上传原图。
- 新增模型、SDK 或云端处理前，先通知成员 6 更新隐私说明。

### 成员 2：协作和任务

**目标：** 老师或管理员能把任务指派给人，大家能看到任务进度。

**要做的事**

- 完成任务 6：把任务指派给某个人，能查看、撤回、完成。
- 完成任务 7：用任务条展示个人任务和指派任务的进度。
- 负责组织、部门、成员管理和相关后台页面。

**最后交付**

- 指派关系能保存到数据库。
- 管理员只能看到自己管理范围内的人。
- Java 和 Python 两个后端行为一致。
- Web 后台和 App 都能正常显示。

**注意**

- 改接口时，要同时改契约文件、Java、Python 和文档。
- 新增数据库字段前，先和成员 6 确认数据要保存多久。

### 成员 3：提醒设置和测试

**目标：** 把闹铃设置页面做好，并把通知功能测清楚。

**要做的事**

- 任务 9：做闹铃设置页面，包括默认值、静音、消息提醒、闹钟三个档位，以及重启后还能记住设置。
- 任务 2：只做测试和验收，检查锁屏、亮屏、后台、点击通知、点“稍后 10 分钟”等场景。
- 写一份 Android 通知测试清单，记录机型、系统版本、复现步骤和截图。

**最后交付**

- 设置页能正常修改并保存。
- 一份可以直接照着操作的通知测试清单。
- 每个问题都能说清楚“怎么复现、原本应该怎样、实际怎样”。

**不需要负责**

- 不改通知的排期和系统通道。
- 不负责让通知在锁屏或后台响起来，这部分由成员 6 做。

**遇到问题找谁：** 通知核心找成员 6；iPhone 推送找成员 5。

### 成员 4：分享入口和语音页面

**目标：** 让用户能方便地从分享、拍照、语音进入识别，并把录音页面做清楚。

**要做的事**

- 任务 11：做分享入口，支持图片识别、拍照、语音三个入口，最后都能进入确认页。
- 任务 10：做语音页面，包括按住说话、录音中、取消、失败、识别中五种状态。
- 用约 10% 的时间做样本标注和简单测试，不负责模型效果。

**最后交付**

- 三个入口都能点通，并跳到正确页面。
- 录音过程中，用户始终知道现在是什么状态。
- 按成员 1 的要求完成标注，提交前由成员 1 抽查。

**不需要负责**

- 不改麦克风权限、录音、上传和语音转文字接口，这些由成员 5 做。
- 不进入 OCR 内部代码，只使用成员 1 提供的入口。

**遇到问题找谁：** 识别入口找成员 1；录音和语音转文字找成员 5。

### 成员 5：iOS 和语音技术

**目标：** iPhone 能安装、能使用；语音从录音到生成日程完整可用。

**要做的事**

- 任务 3：完成 iOS 构建、安装、推送、隐私清单和 App Store 材料。
- 任务 10：完成 Android 和 iOS 的录音、麦克风权限、文件上传、语音转文字、超时和失败处理。
- 帮助成员 4 联调语音页面，帮助成员 3 排查 iPhone 通知问题。

**最后交付**

- 用 EAS 能构建出可安装的 iOS 包。
- 登录、日历、待办、提醒、隐私政策五条主要流程能跑通。
- Android 和 iOS 都能完成“录音 → 上传 → 识别 → 进入确认页”。
- 权限被拒、录音取消、上传失败、识别超时都能回到手动创建日程。

**注意**

- iOS 第一次构建先做技术验证，不要过早承诺 App Store 审核时间。
- 新增 iOS 依赖前，先检查隐私清单和第三方共享清单。
- 语音功能上线前必须做 Android 和 iOS 双端测试。

### 成员 6：提醒核心、合规和技术兜底

**目标：** 让提醒真正可用，同时把公安备案、数据合规和商店上架处理好。

3. 任务 9：闹铃提醒的通知核心。

**要做的事**

- 任务 9：不同声音档位对应的通知渠道和系统行为；设置页面由成员 3 做。
- 公安联网备案：按 `docs/02-合规/公安联网备案-办理指引.md` 推进。

**注意**

- 成员 6 的任务最多，不要平均用力，先把任务 2 和公安备案做完。
- 通知底层和成员 3 的界面分开改，避免互相覆盖。

## 四、大家一起遵守的规则

1. **一个功能只有一个负责人。** 负责人可以找人帮忙，但最后要确认功能能正常使用。
2. **不要直接改别人负责的文件。** 需要改时先在群里说一声，或者让对方提供入口。
3. **成员 3、4 不单独啃核心功能。** 成员 5、6 先搭好能运行的基础，再交给他们补界面或测试。
4. **卡住超过 2 天就转交。** 不要一个人看三四天代码还不说，直接找成员 5 或 6。
5. **不要直接往 `main` 分支提交。** 每个人新建 `feat/功能名` 分支，写完发 Pull Request，至少让一个人检查。
6. **改接口要同步。** 前端、Java、Python 和契约文件要一起改，不能只改一边。
7. **每周说一次进度。** 按“这周做完什么、下周做什么、现在被什么卡住”三句话汇报。
8. **保护项目信息。** 账号、手机号、服务器地址、部署命令不要发到公开群或公开仓库。

## 五、建议排期

### 第 1–2 周

- **成员 1**：准备 20 条评测样本和基线，不急着改模型。
- **成员 2**：搭好任务指派和任务条的数据结构和页面骨架。
- **成员 3**：做任务 9 的设置页，同时写通知测试清单。
- **成员 4**：做任务 11 的分享入口和语音页面骨架，开始样本标注。
- **成员 5**：验证 iOS 构建环境，同时做录音、权限、上传和语音转文字的技术验证。
- **成员 6**：完成任务 2 的通知核心，同时提交公安备案和整理商店材料。

### 第 3–5 周

- **成员 1**：完成解析提速和聊天截图日期推断。
- **成员 2**：完成任务指派、任务条和权限范围。
- **成员 3**：按测试清单回归通知功能，问题交给成员 6。
- **成员 4**：完成分享入口和语音页面状态，继续按周提交标注。
- **成员 5**：完成语音完整链路和 iOS 主要功能、推送。
- **成员 6**：完成任务 2 和任务 9 的通知核心，修复 Android 兼容问题。

### 第 6–7 周

- **成员 6**：完成任务 5 的数据保留、删除机制、合规检查和发布检查。
- **全体**：Android 和 iOS 回归、商店提审、线上问题修复。

### 长期研究线

任务 4/8 不要求马上出成果，按 6–8 周一个阶段推进：

1. 第 1–2 周：准备数据和评测集。
2. 第 3–4 周：做云端基线和实验方案。
3. 第 5–6 周：做小模型或蒸馏实验。
4. 第 7–8 周：做端侧原型，评估速度和准确率。

研究线不能影响正常功能开发。如果以后要恢复 AI 对话，要提前做算法备案和公安安全评估。

## 七、术语解释

| 术语 | 大白话 |
| --- | --- |
| UI / 页面 | 用户看得到、点得到的界面 |
| 后端 | 服务器上处理数据、保存数据的那部分 |
| 前端 / App | 手机上运行的界面和逻辑 |
| OCR | 从图片里认字 |
| ASR | 把语音转成文字 |
| 跨端 | 同一功能要同时支持 Android 和 iPhone |
| 接口 / 契约 | 前端和后端约定“怎么问、怎么答” |
| 回归测试 | 新功能做完后，把以前的功能再测一遍，防止被改坏 |
| 兜底 | 别人做不动时，由更有经验的人接手完成 |
| EAS | Expo 提供的云端 iOS 构建服务，不用自己的 Mac 也能打包 |
| 公安联网备案 | App 或网站上线后要在公安系统做的备案，不等同于 ICP 备案 |
