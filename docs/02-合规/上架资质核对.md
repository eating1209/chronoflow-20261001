## 四、上架前检查

提审要填的每个字段、要传的材料、截图拍摄脚本与 10 项自检，见 `docs/03-上架/应用宝提审清单.md`。

最省事：在构建机（WSL）上一条命令做完「部署后端 → 出包 → 发布 → 验收」：

```bash
cd ~/develop/xa-todo
bash scripts/release_listing.sh
# 已经单独做过某一步：--skip-backend / --skip-apk
```

它会把版本号直接从 `app/app.json` 读成 `1.1.0 / 19`，发布后自动验证
`https://chronocloud.top/downloads/chronoflow-1.1.0.apk` 与隐私政策文本。

只想先看线上现状（不改任何东西）：

```bash
bash scripts/check_live.sh
```

它会分别打印直连 `60.205.142.205:8080` 与 `chronocloud.top` 的返回码，并标出
「旧公司名 / 新公司名 / 陈诗音 / 陶伊婷 / versionCode」，据此判断是 nginx 没反代、
jar 没换，还是 APK 还没发布。

手工分步检查：

```bash
# 合规门禁（必须 --strict）
python3 scripts/check_compliance.py --strict

# App
npm test -w @chronoflow/app && npm run typecheck -w @chronoflow/app

# 后端
mvn -o test
backend-python/.venv/bin/python -m pytest backend-python/tests -q

# 上架包（改了 app.json 的 apiBaseUrl，必须 --prebuild）
bash scripts/build_apk.sh --prebuild --release --archs=arm64-v8a,x86_64
```

另外确认 `https://chronocloud.top/api/v1/system/info` 与
`https://chronocloud.top/api/v1/legal/privacy-policy` 都能在公网直接打开、无登录、无脚本。

> **合规文本是打包进后端 jar 的**（`backend-java/chronoflow-bootstrap/pom.xml` 会把
> `docs/legal/` 复制到 `classpath:/legal/`）。改完公司名 / 极光 SDK 声明后，必须重新打 jar
> 并部署到 `chronocloud.top` 指向的服务器，否则 App 的 WebView 仍会打开旧文本。
