## 三、截图拍摄脚本（6 张）

拍摄前准备：用**演示账号**登录；造 6–8 条日程（标题用「周会」「项目评审」「体检」这类通用词）；
地点用公共地点（如「舟山市图书馆」）；把系统时间调到上午 9:41 左右；关掉通知角标与调试入口。

| 序号 | 页面 | 操作路径 | 画面要求 |
| --- | --- | --- | --- |
| 1 | 日历（主界面） | 底部「日历」 | 能看到当天日程卡片与「点此识别日程，一键添加」入口 |
| 2 | 识别日程确认页 | 日历 → 点此识别日程 → 相册选一张干净的通知截图 → 等识别完成 | 展示识别出的标题、时间、地点，**不要**露出原图里的真实姓名/手机号 |
| 3 | 新建日程 | 日历 → 右下角「+」 | 填好标题、地点、提醒时间，展示提醒与重复入口 |
| 4 | 组织日程 | 底部「组织」（用组织管理员或成员账号） | 展示部门与下发/接收的日程；部门名用「市场部」这类通用名 |
| 5 | 隐私与合规 | 底部「我的」→ 隐私与合规 | 展示隐私政策、已收集清单、第三方共享清单、账号注销四个入口 |
| 6 | 语音输入 | 日历 → 点此识别日程 → 语音输入 → 按住说一句 | 展示按住说话与识别结果；**不要**拍到权限弹窗或其他 App |

**规格与合规**
- 尺寸 1080×1920（或同比例 1080×2400），JPG/PNG，单张控制在 1MB 以内（以后台提示为准）
- 全简体中文，不能出现「测试」「DEBUG」「内网 IP」、二维码、调试浮层
- 必须打码：真实手机号、姓名、学号/工号、身份证号、精确住址、组织内部真实名称
- 截图内容必须与当前版本实际界面一致（审核会对照安装包）

## 四、提审前 11 项自检

1. 首次启动弹出隐私政策，未同意进不了主界面
2. 登录页「同意」默认不勾选
3. 4 步内能打开隐私政策（我的 → 隐私与合规）
4. 账号注销能走通（我的 → 隐私与合规 → 账号注销）
5. 权限都有用途说明（含麦克风），拒绝后不退出、不反复弹
6. 五个合规 URL 公网可打开、无登录、无脚本
7. 安装包包名 / 版本 / 签名与提交信息一致
8. App 内无 502 / 加载失败页（后端已部署、域名已反代）
9. 「检查更新」返回当前发布版本（versionCode 必须递增；`/api/v1/system/app-release`）
10. 截图与实际界面一致，且已打码
11. 测试账号能正常登录，验证码可收到（审核员会实际走一遍）

## 五、常见驳回对照

| 驳回理由 | 对应处理 |
| --- | --- |
| 隐私政策主体与开发者不一致 | 开发者填营业执照全称（无“开发”），不要填简称 |
| App 内无账号注销 | 已有：我的 → 隐私与合规 → 账号注销；提审备注里写明路径 |
| 权限超出功能所需 | `REQUEST_INSTALL_PACKAGES` 用于应用内更新，隐私政策 §9.2 已说明 |
| 截图含测试数据 / 真实个人信息 | 按 §三打码后重拍 |
| 签名与备案不一致 | 换正式 keystore 后做备案变更，再重新提交 |
| 功能描述与实际不符 | 备案备注删掉「系统日历同步」（见 `docs/02-合规/上架资质核对.md` §3.2） |
