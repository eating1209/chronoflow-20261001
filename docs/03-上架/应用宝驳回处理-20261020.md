## 一、驳回内容

1. 【体验问题】APP 无法安装，显示系统不兼容。测试机型：小米 10S / 小米 15 Pro。
2. 【隐私政策】隐私检测未出结果，等结果再核查。

## 二、第 1 条的真因：传了模拟器包

同一个版本我们出过两个包，名字只差一个后缀，**架构完全不同**：

| 文件 | 大小 | 包内 ABI | 能装哪 |
| --- | --- | --- | --- |
| `chronoflow-1.1.0.apk` | 86 MB | `arm64-v8a` | 真手机（小米 10S / 15 Pro 都是这个） |
| `chronoflow-emulator.apk` | 92 MB | `x86_64` | 只有电脑模拟器 |

`x86_64` 是给电脑上的安卓模拟器用的架构，**任何一台真手机都装不上**，
系统提示就是“无法安装 / 系统不兼容”。这次驳回的两台机型都是 arm64，
所以基本可以确定提审传的是 92 MB 那个模拟器包。

**怎么 10 秒确认**：应用宝后台看包的体积——86 MB 是真机包，92 MB 是模拟器包。

## 三、已经做的修复

1. `scripts/build_apk.sh`
   - `--release` 不带 `--archs` 时，**默认出 `arm64-v8a`**（以前默认 `x86_64`，这就是坑）。
   - 只带 x86_64 的 release 包，桌面文件名强制加 `-emulator` 后缀，并在结尾打红字警告，
     避免再和真机包混淆。
2. 新增 `scripts/check_apk.sh`：上传前一条命令检查 ABI / minSdk / 签名 / 16KB 页对齐。
3. `app.json` 版本号 `18 → 19`（被驳回的版本号不复用，避免“版本号已存在”）。

## 五、第 2 条：隐私检测（不是你能手动提交的东西）

应用宝对每个包跑一遍自动隐私扫描，结果一般要 1–3 个工作日才出，**在它出结果之前，
你点什么都不会改变结论**。查看位置：应用宝后台 → 应用管理 → 隐私合规检测 / 安全检测
（或等站内信通知）。

在此期间照常走安装包那条的重新提审，两件事互不影响。出结果后：

- 报告是绿的：不用管，等审核通过。
- 报告标红：报告会点名具体问题（例如“同意前收集设备信息”“申请了未声明的权限”“第三方 SDK 未披露”），
  把报告截图发我，按项改，改完随下一个版本一起提审。

### 我们已经提前去掉的三条高危权限（2026-10-20）

从 APK 的合并清单里查到这三条权限，来源都是**极光推送 SDK 自带**，我们的业务一次都没用到：

| 权限 | 真实用途 | 处理 |
| --- | --- | --- |
| `ACCESS_BACKGROUND_LOCATION` | 极光的地理位置推送（我们没开） | 移除 |
| `READ_PHONE_STATE` | 极光读 IMEI 做设备标识（Android 10+ 本来也读不到） | 移除 |
| `QUERY_ALL_PACKAGES` | 极光判断厂商通道是否安装；我们只用了极光自有通道 | 移除 |

移除方式是 `app.json` 的 `android.blockedPermissions` + 当前 `AndroidManifest.xml` 里的
`tools:node="remove"`（两条都做了：prebuild 不会丢，不 prebuild 也立刻生效）。

**为什么必须去掉**：隐私政策 §9.2 写的是「不会申请…已安装应用列表」，
而包里的 `QUERY_ALL_PACKAGES` 正好打了自己的脸——这种“声明与实际不符”
是隐私检测最常见的扣分项。

出包后验证（应该一条都搜不到）：

```bash
~/Android/Sdk/build-tools/36.0.0/aapt2 dump permissions \
  app/android/app/build/outputs/apk/release/app-release.apk | grep -E "BACKGROUND_LOCATION|READ_PHONE_STATE|QUERY_ALL_PACKAGES"
```
