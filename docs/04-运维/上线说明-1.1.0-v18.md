# 时纪流上线说明 · 1.1.0（versionCode 19）

> 写于 2026-10-19。这一版的目标仍然只有一个：**尽快过审上线**。
> 在 v17（已把 AI 对话「小安」整体摘掉）的基础上，新增**「手机号 + 密码」登录**（可选，与验证码并存）。

| 功能 | 状态 |

| 组织日程、部门、成员、下发 | ✅ 与 15 相同 |

| **登录方式** | ✅ 验证码登录 + **新增「手机号 + 密码」**（在「我的 → 账号与安全 → 登录密码」设置） |

合计 1–3 个月。先把不含对话的版本上架，资质办完再发新版本开放。
AI 的全部代码与文案已归档在 `archive/ai-v1.1/`，恢复步骤见其中的 `RESTORE.md`。

## 一·补、本版新增：手机号 + 密码登录

| 能力 | 说明 |
| --- | --- |
| 登录页 | 顶部可切换「验证码登录 / 密码登录」；密码模式有「还没有账号？立即注册」「忘记密码？」 |
| 注册账号 | 手机号 → 验证码 → 设置密码 → 确认密码 → 注册并登录；验证码证明手机号归属 |
| 设置密码 | 我的 → 账号与安全 → 登录密码（已设置时显示「修改密码」，需原密码） |
| 忘记密码 | 手机号 + 短信验证码 → 新密码（无需登录） |
| 强度规则 | 8–20 位，不能包含空格；前后端同一套规则 |
| 防爆破 | 15 分钟内连续错 5 次锁定，提示改用验证码登录 |
| 会话安全 | 修改 / 重置密码后吊销所有设备的刷新令牌，其它设备需重新登录 |
| 密码存储 | 服务端只存加盐哈希，不保存原文；协议已披露 |

**审核账号**：应用宝要求填「账号 + 密码」。审核期间用 `18006569106 / 730518`
（固定验证码，后端 `CHRONOFLOW_REVIEW_LOGIN_*` 开启，审核后撤销）。
现在有了密码登录，审核员也可以先点「忘记密码」自行设置一个密码，两条路都通。

## 三、上线五步（按顺序执行）

```bash
cd ~/chronoflow-20261001-main

# ① 出包（10–20 分钟；密码换成你自己的）
export CHRONOFLOW_KEYSTORE=$HOME/keys/chronoflow-release.jks
export CHRONOFLOW_KEYSTORE_PASSWORD='你的 keystore 密码'
export CHRONOFLOW_KEY_ALIAS=chronoflow
export CHRONOFLOW_KEY_PASSWORD='你的 key 密码'
bash scripts/build_apk.sh --prebuild --release --archs=arm64-v8a 2>&1 | tail -30

# ② 部署后端（把改好的协议文本推到线上，约 2 分钟）
bash scripts/deploy_backend.sh

# ③ 发布安装包 + 更新发布信息（versionCode 19）
bash scripts/publish_apk.sh app/android/app/build/outputs/apk/release/app-release.apk \
  1.1.0 18 "上架版本 1.1.0：合规文本更新、接入备案域名、版本号更新" --write-env

# ④ 线上自检：直连与域名都应 200，且合规页里没有「小安」「语音」
bash scripts/check_live.sh
curl -s "https://chronocloud.top/api/v1/legal/privacy-policy?v=$(date +%s)" | grep -c "小安\|语音\|麦克风"
```

第 ④ 步最后那条 `grep -c` 应该输出 `0`。

## 三·补、审核账号（提审前必须做，否则应用宝驳回）

应用宝要求填「账号 + 密码」，但我们是短信验证码登录。后端新增了一个**只对审核手机号生效的固定验证码**：
默认关闭，靠两个环境变量打开，审核通过后删掉。

```bash
# ⑤ 在服务器 .env 里写入审核账号（先备份），然后重新部署后端（本次改了这个校验逻辑）
ssh -i ~/.ssh/60.205.142.205-北京.pem root@60.205.142.205 \
  'cp /opt/chronoflow/.env /opt/chronoflow/.env.bak.$(date +%Y%m%dT%H%M%SZ) && \
   grep -q CHRONOFLOW_REVIEW_LOGIN_PHONE /opt/chronoflow/.env || \
   printf "\nCHRONOFLOW_REVIEW_LOGIN_PHONE=18006569106\nCHRONOFLOW_REVIEW_LOGIN_CODE=730518\n" >> /opt/chronoflow/.env'
bash scripts/deploy_backend.sh

# 验证：应返回 "code":0（而不是 20006 验证码错误）
curl -s -X POST https://chronocloud.top/api/v1/auth/login/sms \
  -H 'Content-Type: application/json' \
  -d '{"phone":"18006569106","code":"730518","deviceId":"review-check"}' | head -c 200
```

应用宝里这样填：**账号 `18006569106` / 密码 `730518`**。

⚠️ **审核通过后立刻撤销**：删掉服务器 `.env` 里那两行 → `docker compose up -d backend` 重启 →
再跑上面那条 curl 应返回 `20006`。不撤就等于给这个号留了一把长期钥匙。
