# 模块索引（app/src）

> 目录用英文，给代码和构建工具看；中文名只出现在文档、README 和界面里。
> 新人接手时先在这张表里找到自己那一行，再进对应目录读 `README.md`。

页面多的模块另有 `components/`。测试留在 `app/test/`，不参与边界检查。

## 二、共享底座与装配层

| 位置 | 角色 | 规则 |
| --- | --- | --- |
| `shared/` | UI 组件、主题、API 客户端、定位、错误映射、权限 | **不许 import 任何 `modules/`** |
| `App.tsx` / `runtime.ts` / `context/AppContext.tsx` | 路由注册、全局状态、启动流程 | 可以依赖模块 |
| `api/endpoints.ts` | 全部接口端点（暂未按模块拆） | 装配层，模块可以直接用 |
| `auth/consentStore.ts` | 首启同意的持久化 | 启动期就要用，留在装配层 |

## 三、三条红线

1. 模块之间只能从对方的 `index.ts` / `pure.ts` / `components.ts` 导入，不能进别人内部目录。
2. `shared/**` 不得反向依赖 `modules/**`。
3. 纯逻辑测试只能 import `pure.ts`，不要把 React Native 页面带进 Node 测试环境。

跑一遍检查：

```bash
npm run check:boundaries
```

当前基线：157 个模块、442 条依赖、0 违规。

## 四、领一个模块怎么开工

1. 在 `app/src/modules/<模块>/README.md` 看「管什么 / 依赖谁 / 谁依赖它」。
2. 只改自己模块内的文件；需要动公共能力时，先看 `shared/` 有没有现成的。
3. 需要别的模块的东西，从它的公开入口 import；出口不够用就改那个模块的出口，并在 README 记一笔。
4. 纯逻辑放 `domain/`，测试写到 `app/test/`。
5. 提交前跑：

```bash
cd app && npx tsc --noEmit && node ../node_modules/vitest/vitest.mjs run --silent
cd .. && npm run -s check:boundaries
```

## 五、新增一个模块

1. 建 `modules/<name>/{screens,domain,index.ts,README.md}`。
2. 在 `.dependency-cruiser.js` 的模块清单里登记名字。
3. 在本文第一节表格补一行。
4. 跑 `npm run check:boundaries` 确认没有循环依赖。

## 六、为什么目录不用中文

- 构建链（Gradle / Metro / sourcemap / APK 内 zip 路径）对非 ASCII 路径支持不一致，
  Windows 与 WSL 之间还涉及 GBK/UTF-8 转换，容易出现乱码文件名和缓存失效。
- 脚本与 CI 传中文路径时要额外处理引号、编码，成本换不来收益。
- 英文目录是行业默认，外包、开源、招人都不需要额外说明；中文通过 README 和本文对照即可。
